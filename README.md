# Orchestrate Development V3

Самостоятельный экспериментальный скилл Codex: Luna Max управляет задачей, Astra Low реализует результат, Sol Medium проводит внутреннее ревью, Luna XHigh выполняет исправления и финальную валидацию.

## Требования

Python 3.11+ без внешних библиотек; Codex с нативными субагентами и точным выбором модели/effort или профиля. Доступ к моделям из таблицы ниже обязателен: автоматической подмены нет. Git и аутентифицированный Codex CLI нужны только необязательному Spark-адаптеру.

## Установка

```sh
git clone https://github.com/IBsupermanBI/orchestrate-development-v3.git
cd orchestrate-development-v3
python install.py --project /path/to/project
python install.py --project /path/to/project --apply
```

На Windows используйте, например, `C:/Projects/my-project`; на macOS/Linux — `python3`, если нужно. Первый вызов показывает план без записи. Устанавливаются только файлы manifest: скилл в `.agents/skills/orchestrate-development-v3/`, пять профилей в `.codex/agents/`. Git, кеши, тесты и локальные настройки не копируются.

При конфликте проверьте план и используйте `--apply --force`: старые файлы сохраняются в `.backups/` рядом с обновляемыми файлами. Чужие файлы не удаляются. Повторная установка одинакового пакета ничего не меняет.

Пользовательская установка: `python install.py --user`, затем `python install.py --user --apply`. Корень — `CODEX_HOME` или `~/.codex`; переопределение: `--user --home /path/to/codex-home`.

## Запуск

Выберите основную модель `gpt-5.6-luna` / `max`, затем:

```text
Используй $orchestrate-development-v3 для реализации этапа.
План: <путь или требования>.
Результат и критерии приёмки: <описание>.
```

| Роль | Модель / effort | Профиль |
| --- | --- | --- |
| Владелец процесса | gpt-5.6-luna / max | основная задача |
| Реализация | gpt-6-astra / low | astra-low-worker |
| Исправление | gpt-5.6-luna / xhigh | luna-xhigh-worker |
| Узкая проверка | gpt-5.6-terra / high | terra-high-gate |
| Ревью | gpt-5.6-sol / medium | v3-sol-medium-reviewer |
| Финальная валидация | gpt-5.6-luna / xhigh | v3-luna-xhigh-validator |

Наличие TOML не доказывает его применение. Если среда не выбирает профиль, передаются точные модель, effort и инструкции роли. Свежие ревьюеры не получают историю родителя. Наблюдаемые параметры сверяются, когда платформа их раскрывает.

## Инструкции проекта

Архитектура, контракты, обязательные проверки и разрешения остаются в AGENTS.md проекта. Распределение агентов и механизм ревью принадлежат скиллу. При требовании внешних Loop Review добавьте [согласующий фрагмент](docs/AGENTS.integration.md). Эквивалентное существующее исключение дублировать не нужно. Установщик не редактирует AGENTS.md, config.toml или hooks.json.

## Зависимости

Loop Review не входит в пакет и не вызывается оркестратором. Телеметрия и защита расходов — отдельные необязательные инструменты. Orchestration guard отключён. Коммит и публикация результата требуют соответствующего разрешения.

Опциональный Spark-адаптер и его вспомогательные модули включены; см. [контракт](references/SPARK_ADAPTER.md). Доступность Spark проверяется на конкретной машине, при недоступности используется Luna.

## Состав и проверка

- [SKILL.md](SKILL.md) — инструкции workflow.
- [USER_GUIDE.md](USER_GUIDE.md) — порядок работы.
- `assets/project/.codex/agents/` — профили.
- `references/` — контракты ревью, валидации и Spark.
- `install.py`, `install-manifest.json` — автономная установка.
- `tests/` — проверки пакета без платных модельных вызовов.

```sh
python -m unittest discover -s tests -v
```

Тесты пакета не доказывают качество модельных решений или доступность моделей на аккаунте. Экспериментальный v3 устанавливается рядом с v2, не заменяя его.
