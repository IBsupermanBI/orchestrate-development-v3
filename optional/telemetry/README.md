# Необязательная телеметрия Codex

Пассивный локальный сборщик для анализа времени работы, доступного token usage и использования моделей. Помогает сравнивать затраты на реализацию, ревью, исправления и валидацию. Работает и без скилла оркестрации. MIT, разработчик [IBsupermanBI](https://github.com/IBsupermanBI).

## Установка

Нужен Node.js 22+ в PATH процесса Codex. Из корня репозитория:

```sh
node optional/telemetry/install.cjs
node optional/telemetry/install.cjs --apply
```

Первый вызов — просмотр плана, второй устанавливает сборщик **глобально для всех проектов** в `$CODEX_HOME/hooks/codex-hooks/` (по умолчанию `~/.codex/hooks/codex-hooks/`) и объединяет регистрации в `hooks.json`. Для другого Codex home добавьте `--home /path/to/codex-home`. На Windows пример пути: `C:/Users/your-name/.codex`.

Затем откройте `/hooks` в Codex, проверьте и доверьте определения средствами приложения. При необходимости начните новую задачу или перезапустите приложение. Установщик не изменяет trust hashes. Ручной тест скрипта не доказывает доставку реальных событий приложением.

Скилл устанавливается отдельно через корневой `install.py`; он не включает телеметрию автоматически. Телеметрия не устанавливает профили, orchestration guard или глобальную защиту Astra. Чужие hooks сохраняются. Используется то же место установки, что у standalone codex-hooks: повторная установка заменяет сборщик без дублирования регистраций. Известная старая регистрация `hooks/timesheet.js` снимается; исторические данные не удаляются. Изменённые ставки и billing policy сохраняются. Резервные копии — в `<Codex home>/hooks/backups/`.

## Что собирается

- События начала/окончания сессий, запросов и субагентов, прерывания, ограниченный набор событий инструментов.
- Время, проект/cwd, ID сессии и агента, профиль, явно указанные маркеры скиллов.
- Запрошенные, настроенные и наблюдаемые модель/effort раздельно. Неизвестные профили сохраняются без догадок; известны роли оркестрации и Loop Review 3.1.
- Токены из hook payload или ограниченного чтения локального transcript, когда доступны. Отсутствие значений не считается нулём. Неаддитивные snapshots не суммируются с расходами родителя.
- По умолчанию короткие выдержки: до 2400 символов запроса и результата плюс маркер сокращения после удаления распространённых секретных шаблонов. Полные shell-команды и raw tool outputs не сохраняются.

Чтобы не сохранять текстовые выдержки, задайте `CODEX_TIMESHEET_CAPTURE_TEXT=0` в окружении **процесса Codex до его запуска**. Это не скрывает пути и идентификаторы проекта. Удаление секретов по шаблонам не гарантирует обнаружения любого секрета.

Данные записываются локально в `<Codex home>/timesheets/events-YYYY-MM.jsonl`, месяц — UTC; `.state/` хранит служебные связи и границы событий. `CODEX_TIMESHEET_PATH` задаёт другой файл без автоматической ротации. Сборщик не отправляет данные в сеть и не вызывает модели.

Ошибки сбора не блокируют агента: hook возвращает `{}`. Есть небольшие затраты на запуск Node и запись файлов; ожидание lock ограничено, чтение transcript ограничено 16 MiB. Недоступные события/ID и специальные пути вне hooks не восстанавливаются догадками. Исторический ledger, если существует, читается лишь для необязательных метаданных и не управляет задачей.

## Отчёты

### Глобальный скилл timesheet

В комплект входит [timesheet](timesheet/README.md). Установка из корня репозитория (Python 3.11+):

```sh
python optional/telemetry/timesheet/install.py --user
python optional/telemetry/timesheet/install.py --user --apply
```

Первый вызов показывает план, второй устанавливает скилл в `<Codex home>/skills/timesheet`. Для другого дома добавьте `--home PATH`. Хук и оркестрация не устанавливают его автоматически.

- `$timesheet report` — Markdown за последние 7 дней по текущему проекту, в `.scratch/timesheets/`.
- `$timesheet save` — JSON за тот же период в `.scratch/timesheets/` проекта.
- `$timesheet current` — текущая задача за всё время, включая подтверждённо связанные дочерние задачи и субагентов; без обязательного сохранения файла.

Период и фильтры уточняются обычным текстом. Для `current` при необходимости читаются локальные transcripts выбранных задач. Неполные данные и накопительные снимки показываются отдельно.

В скилле есть [датированный снимок официальных ставок кредитов](timesheet/references/credits.md). Это оценка кредитного эквивалента, не точный процент расхода лимитов подписки. Его ставки независимы от пустого `rate-card.json` генератора ниже.

### Прямой запуск генератора

```sh
node optional/telemetry/report.cjs /path/to/events-2026-09.jsonl --out .scratch/timesheet
```

Создаются `.json`, `.csv`, `.md`. Можно передать несколько файлов и фильтры `--from YYYY-MM-DD --to YYYY-MM-DD --project NAME --model MODEL --workflow NAME`. Пересечения времени учитываются; вычислительное время субагентов отделено от времени основного процесса. Оценки вовлечённости не являются точным учётом человеческого труда.

`rate-card.json` пуст по умолчанию: цены не выдумываются. `--rates /path/to/rates.json` и `--billing /path/to/billing.json` задают свои политики. Оценка стоимости не является фактическим списанием аккаунта. JSONL и отчёты могут содержать приватные данные — не добавляйте их в Git.

## Отключение

```sh
node optional/telemetry/install.cjs --remove
node optional/telemetry/install.cjs --remove --apply
```

Удаляются только регистрации этого сборщика; runtime, история, чужие hooks и защита Astra сохраняются. Если использовали `--home`, укажите его и здесь. Обновите состояние hooks в приложении. Для отката конфигурации используйте резервную копию после сверки более поздних изменений.

## Учёт запросов, целей и полноты (schema 4)

Каждый новый turn получает стабильный `goal_id` с `goal_source=request`. Уточнения в том же turn сохраняются отдельными событиями с тем же ID. Это автоматический учёт заявленных запросов, а не семантическое распознавание бизнес-целей. Окончание ответа записывается в `response_status`; `goal_outcome` остаётся неизвестным без явного подтверждения. Запуски native-агентов связывают дочерний запрос с родительским через `parent_goal_id`, когда событие создания доступно.

Для явной цели или её результата можно передать JSON-файл в пассивный сборщик, без guard:

```json
{"cwd":"/path/to/project","session_id":"VERIFIED_SESSION_ID","turn_id":"VERIFIED_TURN_ID","goal_id":"G1","stage_id":"S1","objective":"Проверить обработку больших объёмов","goal_outcome":"passed"}
```

```sh
node /path/to/codex-home/hooks/codex-hooks/telemetry.cjs --goal /path/to/goal.json
```

`objective`, `stage_id`, `goal_outcome` необязательны. Передавайте только известные идентификаторы и подтверждённый исход; этот вызов сохраняет метаданные, не проверяет результат и не управляет агентом. Данные привязываются к указанному turn; новый turn создаёт новый запрос. Исторические журналы не переписываются.

Запрос и результат сохраняют до 2400 символов плюс маркер сокращения: начало и конец после redaction, с полями `request_truncated` и `result_truncated`. Отключение текстового сбора действует и на этот режим. В служебном state нет текстов запросов и ответов.

Границы повторных запусков считаются по turn и агенту; паузы между завершёнными запусками не включаются в их рабочее время. Уточнение внутри того же turn не сбрасывает начало. Для transcript до 16 MiB доступен полный разбор чисел; для больших файлов читается только хвост до 4 MiB. Его usage — неаддитивный snapshot без подтверждённой модели для ценообразования. Если в хвосте нет подходящей записи, usage остаётся неизвестным.

`timesheet` показывает покрытие данных, наблюдаемый/запрошенный/настроенный effort, отдельные цели и запросы, время их собственных блоков и доступные аддитивные токены/кредиты по агенту, модели и scope. Накопительные snapshots не распределяются по целям и не складываются с дельтами. Последний snapshot заменяет предыдущий, даже если наблюдаемая модель поменялась. По умолчанию тексты в отчёт не входят; для анализа содержания добавьте `--include-text` к report/save/current. Для старых событий используется явно помеченная группировка `legacy_request` по turn, без восстановления обрезанного текста и выдуманных исходов.
